# UI 라이브러리 선택 (D0-1)

목표: 화면을 만들 때 쓸 **라이브러리를 분야별로 정해 두고**(추천순 후보 + 대표의 선택), 구현이 그대로 따르게 한다. 후보·순서는 `scripts/lib-plan.mjs` 의 `CATS` 가 기준이다(인기·버전·라이선스는 도입 전에 공식 사이트로 확인).

## 1. 공통 — 모든 서비스에 항상 넣는다 (질문하지 않고 추천으로 깔고, 바꾸고 싶으면 말하게 한다)
| 분야 | 기본 추천 | 이유 |
|---|---|---|
| CSS 틀 | 스택에 맞는 1순위 | 모든 화면의 바탕 |
| 아이콘 | Lucide | 화면마다 필요 |
| 글꼴(한글) | Pretendard | 한글 글꼴은 라이선스가 확인된 것만 |
| 디자인 토큰·색 | 자체 CSS 변수(`design-tokens.md`) | D3 토큰의 보관 방식 |
| 접근성·품질 검사 | axe-core + Playwright | D4·D6 에서 이미 쓰는 도구 |

## 2. 서비스에 따라 고르는 분야 — 필요한 것만 **분야마다 하나씩 대표에게 묻는다**
| 분야 | 이럴 때 필요 | 유형 기본 |
|---|---|---|
| 컴포넌트 라이브러리 | 폼·표·모달·탭 같은 복합 화면이 4개 이상 | 도구형 |
| 효과·애니메이션 | 소개·감성 화면, 스크롤 연출, 움직이는 일러스트 | 감성·소비자형, 랜딩 |
| 차트·데이터 시각화 | 화면에 그래프·통계·대시보드가 있다 (spec 스토리에서 찾는다) | 없음(`--needs charts`) |
| 게임·3D | 게임 | 게임 |
| 모바일 앱 UI | Expo 등 네이티브 | 모바일 네이티브 |

판단은 `docs/spec.md` 의 스토리·화면 목록으로 한다. 애매하면 필요하지 않은 쪽으로(질문 수를 줄인다).

## 3. 스택 먼저 정한다
`none`(빌드 없는 HTML·Workers) / `build`(npm 빌드 가능) / `react`(React·Next.js). 인터뷰의 선호 스택과 `build/references/stack-templates.md` 로 정한다. **스택에서 못 쓰는 후보는 걸러서 보여 준다**(예: `none` 에서는 shadcn/ui·MUI·Magic UI·Recharts 제외).

## 4. 질문 방식
- 스크립트: `node <atelier>/skills/design/scripts/lib-plan.mjs --type <유형> --stack <스택> [--needs charts,components] [--figma] --write PROJECT.md`
- 출력의 "대표에게 물을 것" 을 **한 메시지로 묶어서** 묻는다(빠른 길). 분야마다 **추천 하나와 이유를 먼저**, 다른 후보와 "쓰지 않기"를 이어 쓴다. 대표는 번호나 이름으로 답하고, "추천대로"면 전부 1순위.
- 꼼꼼한 길이면 분야를 하나씩 묻는다.
- 답을 받으면 `--choose css=pico,charts=chartjs` 처럼 넣어 다시 실행해 PROJECT.md "## UI 라이브러리" 절을 확정한다. 자동 모드는 묻지 않고 `--auto` 로 추천을 채워 "(가정)" 으로 남긴다.
- 쓰지 않기로 한 분야는 `docs/design.md` 에 "쓰지 않음(이유)" 한 줄.

## 5. 적용 규칙
- 이후 단계(D3 토큰·D4 시안·구현)는 "## UI 라이브러리" 절만 읽는다. 라이브러리를 중간에 바꾸려면 절을 고치고 결정 기록에 이유를 남긴다.
- 부품은 라이브러리 것을 쓰고 임의 CSS 는 최소로. 설치·사용법은 **공식 문서(가능하면 MCP)의 최신 내용**을 따른다 — 명령을 이 문서에 외워 두지 않는다(버전이 자주 바뀐다).
- shadcn/ui 를 고르면 shadcn MCP, Figma 디자인이 있으면 Figma MCP 설치를 권한다(선택).
- **유료(Pro) 판은 쓰지 않는다.** 라이선스·출처를 `docs/design.md` 에 기록하고 guard G5 에서 다시 본다.
- 이미 만든 화면의 라이브러리를 바꾸는 요청이면 영향받는 화면 목록을 먼저 보고하고 확인받는다.
